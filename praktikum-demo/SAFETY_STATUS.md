## Подтверждено
- Разработка и публикация в исходном репозитории: `mafiadjeck-cmd/mafiadjeck-cmd.github.io`.
- Работающий сервер подключён к `main` с автоматическим деплоем; **не изменять `main` до резервирования данных**.
- Действующий API использует Render Free и хранилище `praktikum-cms-store` Free с `persistenceMode=off`; **сохранность опубликованного HTML и статистики при перезапуске не гарантирована**.
- Статическая запасная версия сайта присутствует в `praktikum-demo/base.html`, но она **не гарантированно равна последней версии из CMS**.
- В тестовой админке ключ больше не записывается в `sessionStorage`; серверная авторизация пока основана на общем ключе, полноценная авторизация не внедрена.
- В тестовом сервере статистика считает уникальные посещения с `PFCOUNT` по нескольким ключам без создания `PFMERGE`/удаления временного ключа. Учесть, что Redis документирует возможные внутренние изменения кеша кардинальности при `PFCOUNT`.
- В тестовом сервере `/health` возвращает `publishedStored`, а `/site` выставляет заголовок `X-Praktikum-Content-Source` (`redis` или `fallback`).
- В `praktikum-cms-server/tests/staging-safety.cjs` добавлены автономные проверки структуры и синтаксиса.
- В тестовой ветке добавлен корневой `.gitignore` с правилами только для `praktikum-cms-server` и `praktikum-demo`, чтобы случайно не добавить секреты и дампы в Git; существующие ранее опубликованные секреты (если были) этим не удаляются.
- Подготовлен отдельный локальный набор read-only экспорта Redis и автономной проверки зашифрованного архива. 10 автономных тестов пройдены, **настоящую выгрузку Redis не выполняли**.
- Тестовая админка экранирует символы открытия тегов в `site-data` JSON, временно отделяет сериализованный JSON от HTML-подстановок, экранирует контактные значения и проверяет HTTPS-ссылки социальных сетей по разрешённым доменам.
- Для тестовой серверной части добавлен `npm test`; регрессионные проверки HTML/JSON и ссылок выполняются в автономном режиме, без подключения к Redis.
- Попытка получить внешний ответ `/health`, `/meta` через обычный веб-просмотр не удалась; доступность работающего API **этим способом не подтверждена**.
- В тестовом `praktikum-demo/index.html` добавлено ограничение ожидания CMS до 4 секунд через `AbortController` и сообщение о загрузке. После неудачи он открывает `base.html`, который **может отставать от текущего Redis**. Три автономных сценария загрузчика (успех, HTTP 503, тайм-аут) прошли.

Экспорт **не требует менять доступ Redis**, шифрует снимок, умеет проверять и извлекать HTML/агрегированную статистику; он **не копирует ключи Redis**. Набор инструментов локально проверен: 20 из 20 автономных тестов, ZIP архив прошёл контроль целостности. Боевые данные не получены, HTTP-ответ работающего API из текущего инструментария недоступен.
- Публичная страница из GitHub `base.html` существует как код в репозитории, но соответствие текущей опубликованной версии CMS **не доказано**.

## Интеграционный тест CMS и Redis — 31.10.2026

**Подтверждено реальным запуском**: [GitHub Actions 41194547373](https://github.com/mafiadjeck-cmd/mafiadjeck-cmd.github.io/actions/runs/41194547373), статус `success`, 18 из 18 прикладных проверок успешно.

- GitHub Actions создал **эфемерный Redis 7.4 в отдельном Docker-контейнере**; веб-сервер запущен из `praktikum-cms-server/server.js` тестовой ветки с отдельным ключом и адресом локального тестового HTML. Производственные переменные окружения/Redis, `main` и настройки Render не использованы и не изменены.
- Через настоящий HTTP API проверены `GET /health`, `GET /site` (fallback/Redis), `GET /meta`, `POST /publish`, `POST /event`, `GET /stats`, отклонение неправильных данных, проверка административного ключа и запрет чужого Origin.
- Временная база №14 содержала только **синтетические тестовые данные**: HTML, агрегированные посещения, HyperLogLog для уникальных посетителей и TTL. Сняты 11 двоичных копий `DUMP` (типы `string` / `hash`), восстановлены командой `RESTORE` в отдельную БД №15 с сохранением срока жизни.
- CMS с восстановленной БД вернула исходный HTML, тот же `updatedAt` и те же totals/uniqueVisitors. Повторный запуск процесса CMS сохранил состояние базы. Данный сценарий **НЕ демонстрирует перезапуск/отказ самого Redis, гарантию сохранения данных на Free-тарифе Render, миграцию другой версии Redis или восстановления реального дампа клиента**.
- Тест ограничен GitHub-хостинговой средой (отдельный Redis 7.4). Текущий сервис Render использует Valkey 8.1.10, поэтому реальную совместимость `DUMP/RESTORE` между этими движками надо отдельно проверить на независимых копиях данных и без затрагивания рабочего хранилища.
- Скрипт: [integration-redis.cjs](../praktikum-cms-server/tests/integration-redis.cjs); workflow: [praktikum-isolated-redis-restore.yml](../.github/workflows/praktikum-isolated-redis-restore.yml).
- До переноса критически необходимы **полная резервная копия текущих ключей Redis/Valkey** и отдельная проверка восстановления именно этих данных.
