# Практикум — план единовременного резервного копирования реального Valkey

**Дата:** 31.10.2026. **Состояние:** НЕ ВЫПОЛНЕНО. Документ относится только к ветке `safety/praktikum-backup-only-2026-10-31`, созданной из текущего `main`, а не к большой ветке улучшений.

## Зачем отдельная ветка

Тестовая ветка остальных улучшений отличается от `main` на десятки коммитов, поэтому переносить её ради резервирования опасно. В этой ветке изменён только действующий файл `praktikum-cms-server/server.js` (добавлен выключенный по умолчанию маршрут); остальные файлы — код выгрузки, локальные утилиты, тесты и этот документ. Все действующие маршруты CMS не должны быть изменены.

**НИЧЕГО НЕ СЛИВАТЬ И НЕ РАЗВЁРТЫВАТЬ, пока нет отдельного разрешения владельца и готового плана отката.**

## Критически важное о текущей системе

- Render сервис `praktikum-cms-api` автоматически разворачивается из `main`.
- Render Key Value `praktikum-cms-store`: тариф Free, `persistenceMode=off`. Нельзя перезапускать Valkey или менять его настройки ради этой процедуры.
- Текущий публичный HTML уже сохранён отдельно из `GET /site`. Это не является полной резервной копией Valkey (нет исторической статистики и всех ключей).
- Экспортёр может читать `praktikum:*`, но он **не делает моментальный RDB/AOF-снимок**: `SCAN` неатомарен; статистика может изменяться во время чтения.
- Доступа к реальным ключам через имеющийся Render connector нет. Пока ветка не развернута и маршрут не разрешен, никакого экспорта реальной БД не произошло.

## Предварительный контроль (не пропускать)

1. Убедиться, что у владельца есть административный доступ к Render, GitHub и безопасный локальный компьютер с Node.js. **Не отправлять секреты в чат, GitHub, логи или скриншоты.**
2. Скачать и проверить текущую опубликованную страницу и метаданные `GET /site`, `GET /meta`. Повторно проверить, что HTML отвечает актуальной публикации и содержит клиентские правки. Сохранить снимок в защищённом месте.
3. Зафиксировать последний SHA `main`, состояние веб-сервиса, контрольные URL, время публикации, признаки работы статистики. Проверить готовность отката при сбое. Предупредить владельца, что обновление веб-сервиса Render может вызвать краткую недоступность.
4. Наличие протестированной зашифрованной копии **реального** Valkey должно стать обязательным условием последующих миграций. Сохранённая HTML-страница — только аварийная страховка публичной части.
5. Проверить GitHub Actions `Praktikum minimal backup-only branch QA` на Redis 7.4 и Valkey 8.1.10, тесты отказа, восстановление в пустую DB15, проверку HTML и статистики через CMS. Не принимать неуспешные или устаревшие тесты.

## Единовременное разрешённое включение (только после отдельного согласия)

1. Выпустить **только** минимальный проверенный патч, ни одной другой функции из общей `staging`. `main` и Render изменяются только после самостоятельного утверждения. Убедиться, что весь остальной сайт и админка остались неизменны.
2. В Render безопасно задать одновременно отдельный секрет `BACKUP_EXPORT_KEY` (не менее 32 символов, иной, чем `ADMIN_KEY`) и `ENABLE_BACKUP_EXPORT=true` для `praktikum-cms-api`. Не менять `REDIS_URL`, `ADMIN_KEY`, тариф или сам сервис Valkey. Изменение переменных окружения может вызвать повторный деплой веб-сервиса.
3. Прежде чем скачивать архив, проверить `/health`, `/site`, `/meta` и работу админки **без публикации изменений**. Проверить, что `POST /backup/export` отвечает 401 без двух ключей, а не раскрывает содержимое.
4. Запустить с доверенного компьютера из папки репозитория: `node praktikum-cms-server/backup/download-encrypted.cjs`. Ключи и пароль архива вводить только в скрытые запросы терминала. В случае ошибки ничего не повторять бесконечно, выяснить причину по статусу.
5. Получить зашифрованный файл, сверить SHA-256, расшифровать локально, подтвердить наличие `praktikum:published:html`, `praktikum:published:updatedAt`, требуемых ключей статистики и соответствие опубликованной странице. Убедиться, что архив не пуcтой и зафиксировать число ключей, размеры и таймстемпы.
6. В отдельном **пустом локальном** Valkey совместимой версии выполнить `node praktikum-cms-server/backup/restore-isolated.cjs /путь/к/архиву.json`. Утилита жёстко ограничена `redis://127.0.0.1:6379/15`, запрещает непустую базу и требует подтверждения. **Не направлять её в реальный Redis, не выполнять FLUSHDB/RESTORE на клиентском Valkey.**
7. Вновь запустить тестовую CMS только с локальной DB15 и тестовыми секретами. Сверить HTML, дату публикации, статистику и уникальных посетителей (с учётом того, что события могут поступать во время неатомарного сканирования).
8. Только после проверки сохранить архив как минимум в двух независимых защищённых местах, пароль — отдельно. Нельзя считать выгрузку надёжной без проверенного восстановления.
9. Сразу выключить `ENABLE_BACKUP_EXPORT`, удалить `BACKUP_EXPORT_KEY`, проверить ответ 404 у маршрута, сайт, админку и статистику. Смена переменных может повторно перезапустить веб-сервис.
10. Решение о переходе на устойчивое хранилище и регулярном резервировании принимать **после** этого этапа, отдельно; Free Valkey с `persistenceMode=off` остаётся риском даже после одной удачной копии.

## Немедленная остановка и откат

При неуспешной авторизации, 503/500, отсутствии опубликованного HTML, смене версии в ходе экспорта, незапланированной недоступности сайта, несовпадении данных после восстановления или повреждении архива:
- **Не выполнять повторные публикации в CMS, не восстанавливать ничего в рабочий Valkey и не перезапускать хранилище.**
- Отключить временный маршрут и удалить временный секрет. При необходимости вернуть веб-сервис на заранее зафиксированную рабочую ревизию.
- Проверить публичную страницу и актуальную статистику, сохранить журнал с маскировкой секретов.
- Зафиксировать инцидент и причины до следующей попытки.

## Что разрешено без отдельного согласия

Работа с отдельными GitHub-ветками, кодом и тестовыми Valkey в GitHub Actions; чтение публичных GET URL и метаданных без секретов. **Слияние в main, изменения Render environment, перезапуски и подключение к живому Valkey — только с разрешения.**
